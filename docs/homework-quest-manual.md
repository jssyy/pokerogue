# 作业勇者 · 操作手册

给**家长**看的说明书：怎么把它跑起来、每天怎么用、出问题了怎么办。

只想知道这套东西为什么这么设计（分数为什么换成体力、星级怎么定价），看 [homework-quest.md](homework-quest.md)；只关心账号服务的内部实现，看 [server/README.md](../server/README.md)。

---

## 一分钟版

```bash
pnpm play
```

浏览器打开 **http://localhost:8000** 玩，**http://localhost:8001** 管账号。`Ctrl+C` 一起停掉。

---

## 一、第一次安装

### 需要什么

| 项目 | 要求 | 怎么确认 |
| --- | --- | --- |
| Node.js | **24.9 以上** | `node -v` |
| pnpm | 随 Node 自带的 corepack 即可 | `pnpm -v` |
| 磁盘 | 约 3 GB（素材子模块占大头） | — |

### 装

```bash
git clone <你的仓库地址> pokerogue
cd pokerogue
pnpm install
pnpm update-submodules
```

`pnpm install` 之后 `assets` 和 `locales` 两个子模块必须拉下来，否则游戏加载到一半会卡住找不到图。

### 建家长账号（只做一次）

```bash
pnpm play
```

打开 **http://localhost:8001**，页面上会出现「建立家长账号」按钮 —— 这个按钮**只在数据库里一个账号都没有的时候出现**。填好用户名密码建立。

> 之后注册接口就关掉了。孩子账号只能由家长创建，所以就算有人扫到这个端口，也找不到可以注册的入口。

### 建孩子账号

还在 8001 那个页面，登录家长账号 → 「新建孩子账号」→ 填用户名、密码、昵称（昵称是游戏里显示的名字，可以是中文）。

新建的孩子账号**由服务端直接发 30 点体力**，够开一局，不至于第一次打开就是一扇打不开的门。

## 二、每天怎么启动

```bash
pnpm play
```

一条命令同时起两个服务：

| 地址 | 是什么 | 谁用 |
| --- | --- | --- |
| http://localhost:8000 | 游戏 | 孩子 |
| http://localhost:8001 | 账号管理页 | 家长 |

启动器会先把两个端口清出来：如果上次留下的进程还在，它会认出来并停掉；如果占着端口的是**别的程序**，它不会乱杀，而是报出端口号让你自己确认。

任何一半挂了会**自己重启**（1 秒后），另一半不受影响。一分钟内连挂 5 次才判定为真故障，那时整体停下并让你去看日志。

### 别的启动方式

| 命令 | 用途 |
| --- | --- |
| `pnpm play` | **日常用这个。** 游戏 + 账号服务 |
| `pnpm start:family` | 只起游戏（账号服务已经在别处跑着时） |
| `pnpm start:server` | 只起账号服务 |
| `pnpm restart:server` | 重启账号服务（会先停掉旧的） |
| `pnpm start:dev` | 开发模式，**跳过登录**直接进游戏，不连账号服务 |

`start:dev` 不是给孩子用的：它绕过登录，进度只在浏览器里，换个浏览器就没了。

## 三、让手机 / 平板也能玩

游戏本身是网页，手机浏览器能玩，触屏按钮已经适配。要在同一个 Wi-Fi 下的别的设备上打开，需要三步：

**1. 查这台机器的局域网 IP**

```bash
ipconfig
```

找 `IPv4 地址`，形如 `192.168.1.20`。

**2. 改 `.env.family`**，把 `localhost` 换成这个 IP：

```
VITE_SERVER_URL=http://192.168.1.20:8001
```

孩子的手机连的是手机自己的 `localhost`，不是你的电脑 —— 这一行不改，手机上登录必然失败。

**3. 让游戏对外监听**

```bash
node node_modules/vite/bin/vite.js --mode family --host
```

`pnpm play` 目前只监听本机，对外要加 `--host`。账号服务本来就监听所有网卡，不用改。

然后手机浏览器打开 `http://192.168.1.20:8000`。

> Windows 防火墙第一次会弹窗询问，选「允许专用网络」。

## 四、家长怎么用

### 进入家长模式

**登录着家长账号时不需要任何额外操作** —— 打开计划页就已经是家长模式，标题栏会写着「作业勇者　家长模式　小明」，告诉你现在看的是谁的计划。

只有在**没有账号、离线玩**的模式下，才会出现「家长模式」菜单项，用 4 位 PIN 进入（初始 `1234`，进去后请到「家长设置」改掉）。

### 排计划

计划页 → 左右方向键换日期 → `菜单… → 新建任务` → 选科目 → 选模板或自己输标题 → 选必做/选做。

`菜单… → 复制昨天的计划` 适合作业结构稳定的日子。

### 打分（**只有家长能做**）

选中一项已提交的任务 → `确定` → 「给这项打分」→ 选 1~5 星。

| 星级 | 体力 |
| --- | --- |
| ★ | 2 |
| ★★ | 5 |
| ★★★ | 10 |
| ★★★★ | 18 |
| ★★★★★ | 30 |

额外加成：

- 当天**必做全部打完分**：+10
- 当天**平均 4 星以上**：再 +20
- **连续天数**：每天 +3，最多按 7 天算
- 计划日之后**超过 1 天才打分**：体力**减半**

> 一次认真的 5 星（30）胜过五次敷衍的 1 星（10）—— 这个坡度是故意的。

打分会**立刻记到服务器**。孩子在别的设备上下次打开计划页就能看到。

### 切换孩子

`菜单… → 切换孩子`。有多个孩子时打开计划页会自动选中第一个，标题栏始终写着当前是谁。

### 家长设置

`菜单… → 家长设置`：

| 项 | 说明 |
| --- | --- |
| 切换体力门禁 | 关掉后随时能玩，游戏回到 PokéRogue 原本的标题界面 |
| 今天免体力 | 生病、放假、亲戚来了 —— 只对今天生效 |
| 赠送 50 体力 | **必须先选中一个孩子**，体力发到孩子账号上 |
| 修改家长密码 | 只在离线 PIN 模式下有意义 |
| 导出问题日志 | 出 bug 时给我看这个文件（见第七节） |

### 管理账号（8001 页面）

登录家长账号后可以对每个孩子：**改昵称 / 改密码 / 停用 / 删除**。

- **改密码**会把该孩子所有已登录的设备踢下线。
- **停用**不删数据，随时能恢复 —— 用它做「这周先别玩了」。
- **删除**需要输入孩子的用户名确认，**进度不可恢复**。想暂停请用停用。

### 忘记密码了

**孩子的密码忘了** —— 家长在 8001 页面上「改密码」就行，一分钟的事。改完那个孩子所有已登录的设备会被踢下线，用新密码重新登录即可。

**家长自己的密码忘了** —— 没有任何网页入口可以找回：注册接口在建完第一个账号后就关掉了，家长之上也没有别人可以求助。这种情况在**跑着服务的那台机器上**用本机工具改：

先看看数据库里都有谁（不带参数，什么都不会改）：

```bash
node --experimental-sqlite server/scripts/reset-password.mjs
```

```
账号一览：
  syy　家长　syy
  syf　孩子　史益凡
```

然后改：

```bash
node --experimental-sqlite server/scripts/reset-password.mjs syy 新密码至少4位
```

- 改完会**踢掉该账号所有还登录着的设备**，和管理页上改密码的行为一致
- **家长身份不受影响**，改的只是密码
- 服务**不用停**，改完立刻生效
- 孩子的密码也能用这个工具改，效果和管理页一样

> 这不是后门。它需要你能登进那台机器、并且能读写数据库文件 —— 有这两样的人本来就能把库里任何一行读出来改掉。它只是省掉手写 SQL。
>
> 也正因如此：**别把 `server/data/` 目录连同数据库随便拷给别人。**

## 五、孩子怎么用

1. 打开 http://localhost:8000，用家长给的账号登录
2. 计划页看今天要做什么，做完一项选中它 → `确定 → 我做完了`
3. 等家长打分 → 体力到账
4. 体力够了，第一行「出发冒险」

| 花费 | 数量 |
| --- | --- |
| 开新的一局 | 30 |
| 继续上次的局 | 10 |
| 每打过 10 波 | 10 |

菜单里还有：

- **学习商店** —— 体力换蛋券：普通蛋券 60 / 高级蛋券 150 / 特级蛋券 400 / 糖果雨 80（3 只已收服宝可梦各 +5 糖果）
- **我的账本** —— 体力从哪来、花到哪去，逐条可查
- **游戏指南** —— 新标签页打开的图鉴与道具说明
- **规则说明** —— 星级换体力的规则
- **换个账号登录** —— 家长要用同一台设备批改时用这个

孩子账号看不到任何家长的选项 —— 那些行根本不会被渲染出来，而不是藏起来。

## 六、数据在哪、怎么不丢

```
server/data/family.sqlite        账号、存档、作业计划、体力记录
server/data/backups/             每 6 小时一份整库备份，保留 28 份（约一周）
```

三道保险：

1. **每次覆盖存档都留旧版本**，每个存档位保留最近 **20** 份。「存档没了」变成「回滚一版」。
2. **定时整库备份**，WAL 模式下热拷贝，不用停服。
3. **写入立刻落盘**（`synchronous = FULL`）。

### 手动备份一份

```bash
node --experimental-sqlite -e "const{DatabaseSync}=require('node:sqlite');new DatabaseSync('server/data/family.sqlite').exec(\"VACUUM INTO 'server/data/backups/manual.sqlite'\")"
```

`VACUUM INTO` 会把 WAL 里还没落盘的内容一起写进去，比直接复制 `.sqlite` 文件可靠 —— 直接复制很可能只拿到一个几 KB 的空壳。

### 从备份恢复

停掉服务，把备份文件改名成 `family.sqlite` 放回 `server/data/`，删掉同目录下的 `-wal` 和 `-shm` 两个文件，再启动。

## 七、出问题了

### 「服务器连接失败」

先看服务是不是还在：

```bash
curl http://127.0.0.1:8001/health
```

回 `ok` 就是活的。不回就 `pnpm play` 重启。

结算时连不上**不会**让这一局作废 —— 战绩和结算画面都会保留，只是当天的每日挑战通关不上报。

### 端口被占用

启动器会自己处理上次留下的进程。如果它报「端口被别的程序占着」：

```bash
netstat -ano | findstr :8000
```

拿到 PID 后在任务管理器里确认那是什么再决定。

### 孩子登录后体力是 0

1. **硬刷新一次**（`Ctrl+F5`）—— 这类问题多半是页面里残留的旧状态
2. 确认账号服务活着（上面那个 `/health`）
3. 在 8001 页面上确认登的确实是孩子账号，不是家长账号

### 小窗口里登录框点不动 / 光标位置不对

已修复。如果还遇到，先硬刷新。

### 登不进去 / 密码不对

看第四节的「[忘记密码了](#忘记密码了)」。孩子的密码家长在 8001 页面就能改；家长自己的密码要在服务器那台机器上用 `server/scripts/reset-password.mjs` 改。

### 卡在加载画面

第一次启动、或刚装过新依赖时，加载会慢很多（冷启动跑到 100% 可能要几分钟），这是正常的。之后就快了。

真卡住的话按 F12 看控制台有没有红色报错。

### 导出问题日志给我

`菜单… → 家长设置 → 导出问题日志`，下载文件夹里会多出一个 `.txt`。里面是最近 300 条界面切换、按键和报错记录，比「它坏了」有用得多。

## 八、维护

### 跑测试

```bash
npx vitest run test/tests/ui test/tests/system
```

改过作业相关代码后跑这个，几分钟。全量 `pnpm test` 很慢。

### 合并上游的新版本

```bash
git fetch origin
git tag -f pre-merge-$(date +%Y%m%d) HEAD      # 后悔药
git merge origin/beta
```

冲突通常只有个位数，且集中在**我们的代码正好挨着上游改动的那几行**。解决后必须：

```bash
pnpm install                      # 上游经常升依赖
pnpm update-submodules            # locales 指针会跟着动
npx tsc --noEmit                  # 上游改过的 API 我们可能还在用旧的
npx vitest run test/tests/ui test/tests/system
```

**`tsc` 这一步不能省。** 上游删过 `ui.getMode()` 这类方法，我们几处代码还在调用 —— 合并那一刻不报任何错，跑起来才炸。

后悔了就 `git reset --hard pre-merge-YYYYMMDD`。

## 九、几条边界

- **孩子无法给自己发体力。** 服务端只认家长身份，孩子的请求会被 403 拒掉 —— 不是把菜单藏起来那种「拦」。
- **体力"挣得"归服务器，"花掉"归客户端。** 花自己的余额只会变少，没有说谎的动机；这也让服务器关着的时候孩子还能继续玩。
- **会话不过期。** 在家里，会话过期的代价是孩子玩不了、要等家长，比它防住的风险更糟。
- **两台设备同时改同一份计划不会合并**，后写的覆盖先写的。一家人用，这比一套没人能看懂的合并逻辑诚实。
- **停用不等于删除**，没有任何接口会删掉孩子的进度。
